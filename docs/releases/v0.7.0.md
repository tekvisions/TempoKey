TempoKey 0.7.0 combines the planned macOS 0.3–0.7 milestones into one release: a track library, exports and tagging, playback, deeper analysis, and live audio input.

**Download:** `TempoKey-0.7.0.dmg` — universal Apple Silicon + Intel, **macOS 14 or newer**. The app and DMG are Developer ID signed, notarized, and stapled. Build number: **4**. A SHA-256 checksum file is included.

## Library and batch analysis

- Import multiple audio files or whole folders through the native picker, ⌘O, or drag-and-drop anywhere in the window.
- Recursively discover supported files, skip hidden files/packages and symbolic links within folders, deduplicate paths, and process files in deterministic order.
- Analyze files off the main thread with a memory-bounded serial queue, overall progress, the current filename, and cancellation.
- Keep successful results when another file fails; show individual failures and cancelled items in the library.
- Sort tracks by filename, BPM, key, Camelot notation, or duration. Open reports by button or double-click.
- Preserve each track's corrections while navigating the current session; returning to the library keeps an active batch running.
- Persist up to twelve recent imports using security-scoped bookmarks, with reopen and clear controls.

## Corrections and native interface

- Add Open Key notation alongside standard key names, Camelot codes, and compatible-key hints.
- Enter a manual BPM and press Return; retain tap tempo, half/double tempo, manual key selection, reset, and copy-summary controls.
- Make tap tempo responsive to changing rhythm by using the latest eight taps and resetting tap history when changing tracks.
- Mark corrected summaries explicitly; show a dash when tempo evidence is insufficient.
- Add a new import/home screen, native material-backed controls, library navigation, transport controls, a scrollable report, and section navigation.
- Persist System/Light/Dark appearance. Use a single main window to avoid competing shared-state windows.

## Exports and metadata

- Export the sorted library as CSV, including displayed BPM/key/Camelot, duration, detected values, and whether corrections were applied.
- Quote CSV fields correctly and guard filenames that spreadsheet applications could interpret as formulas.
- Export versioned, readable JSON containing the full detected analysis and explicit corrected values.
- Export a high-resolution PNG report with summary, tempo/key/beat timelines, time ruler, and relative energy.
- Save tagged **audio copies**, preserving original files. Reject source paths and symlink/hard-link aliases as destinations.
- MP3: write BPM (`TBPM`), initial key (`TKEY`), and `TEMPOKEY_CAMELOT` user-text metadata in supported ID3v2.3/v2.4 tags, retaining unrelated frames and the audio payload.
- M4A: use passthrough export, write native BPM metadata, retain existing metadata/comments, and append key/Camelot information to the comment.
- Report unsupported formats/tag variants explicitly; stage exports inside the sandbox and atomically save to the selected destination.

## Playback and synchronization

- Add play/pause, a seek slider, elapsed/total time, and a playhead shared across report timelines.
- Click the timeline to seek; retain pinch/scroll zoom, drag-to-pan, double-click reset, and the full-track minimap.
- Loop the visible timeline region and toggle an audible click at detected beat times.
- Add Space for play/pause and ⌘←/⌘→ for five-second seeking.
- Stop playback and release file access when changing tracks, entering live input, or closing the main window; handle EOF and loop restarts.

## Deeper musical analysis and accuracy fixes

- Add RMS energy curves and numbered sections based on sustained energy or tempo changes, with each section's median local BPM.
- Detect tempo changes even when energy stays constant; deduplicate nearby boundaries and reject jitter, half/double-time ambiguity, and short false tempo plateaus.
- Estimate 3/4 or 4/4 meter and downbeats only when repeated accents provide sufficient evidence; otherwise leave meter undetermined.
- Normalize PCM to 44.1 kHz so detector timing is consistent across source and device rates. Fix incorrect/missing BPM at low and high sample rates, with regressions at 8, 96, and 384 kHz.
- Fix overlapping key segments, transition double-counting, short-clip coverage, and missing final key coverage.
- Reject empty, silent, non-finite, excessively long, or invalid-rate audio; avoid presenting a tempo consensus for clips under four seconds.
- Check cancellation throughout decoding, resampling, and DSP; prevent obsolete tasks/progress callbacks from replacing newer results.

## Live input

- Add explicit start/stop controls and microphone permission handling, including a useful denial message.
- Select the system default or a Core Audio input device, refresh the device list, and display an input level and current BPM/key/Camelot estimate.
- Warm up with six seconds of audio and analyze a fixed-capacity rolling window of up to twelve seconds, with at most one analysis job active.
- Show warming-up, silence, device-change, and error states. Discard stale permission/analysis callbacks after stop or restart.
- Stop capture when leaving live mode or closing the main window; unrelated window closures no longer stop capture.
- Analyze locally without saving or uploading live audio. The optional GitHub update check sends no audio.

## Core, distribution, and documentation

- Add Codable/Equatable/Sendable analysis models with backward-compatible defaults for new fields.
- Introduce decoder, resampler, FFT, and window-generation interfaces while retaining the Apple AVFoundation/Accelerate implementations; add a bounded PCM-buffer helper.
- Update sandbox entitlements for user-selected read/write access, app-scoped bookmarks, and microphone input; add the microphone privacy purpose string.
- Disable base-entitlement injection in Release so `get-task-allow` is absent; retain the separate Debug configuration needed by hosted XCTest.
- Add universal-architecture verification and make Gatekeeper acceptance a required packaging check.
- Include the project's MIT license and full upstream beat-tracking MIT notice in the app bundle; preserve the upstream privacy clarification.
- Update README/build instructions, roadmap status, validation records, and design/implementation documentation.

## Verification and known limits

- **83 automated tests pass:** 49 core tests and 34 hosted app tests. Debug tests and the Release build pass; independent review findings were fixed and rechecked.
- Native sandboxed-app checks covered folder import, batch results, report rendering, numeric corrections, M4A export outside the imported folder, playback controls, recent-folder reopening after relaunch, and light/dark interface smoke checks.
- Musical estimates should be checked by ear. Sections are neutral numbered regions, not claimed intro/build/drop classifications. Meter currently supports conservative triple/quadruple accent patterns, not compound or irregular meters; confidence is heuristic.
- Corrections and analyzed library results are session-local; recent import locations persist. The metronome follows detected beats, not a manually corrected summary BPM.
- Tagging supports common MP3 ID3v2.3/v2.4 variants and M4A. M4A key/Camelot data is stored in comments rather than DJ-specific key atoms. FLAC/WAV tagging and unsupported ID3 variants are not included.
- Real-device microphone permission/reconnection, extended live capture, audible metronome/loop timing, external-drive behavior, exhaustive accessibility, long-file profiling, and a broader real-music accuracy corpus still need validation. Intel and minimum-macOS runtime testing remain distinct from universal compilation.
- **Windows and iOS are not included**; this release is macOS first.
