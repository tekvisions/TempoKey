# TempoKey 0.7.1

macOS stabilization release. Requires macOS 14 or later; universal Apple Silicon/Intel DMG.

## Analysis fixes

- Stop reporting stale tempo and predicted beats through sustained digital silence.
- Reset the tempo histogram after silent breaks so resumed music can establish a new tempo.
- Smooth each continuous run of tempo evidence independently. A short resumed section no
  longer inherits the pre-silence tempo or an invented midpoint.
- Compute whole-track tempo evidence from agreement among local estimates, with a short-track
  penalty and a ceiling below certainty. The final histogram peak no longer determines the
  confidence of an entire song.
- Exclude zero-evidence key segments from overall-key voting. Long silent passages no longer
  turn a track's key into C major; silent C-major placeholders stay separate from musical
  segments. Equal-duration key ties now resolve deterministically.

## Report and navigation

- Replace percentage confidence with **strong / mixed / weak tempo evidence**, including an
  explanation that the score is not a probability of correctness.
- A key-only correction no longer incorrectly labels the BPM as corrected.
- Break tempo chart lines at missing-evidence gaps; hover readouts no longer borrow a distant
  tempo from across silence.
- Render key segments without tonal evidence neutrally, including the overview and PNG report.
- Add earlier/later timeline buttons, explicit zoom accessibility labels, and an adjustable
  accessible overview with its visible time range.
- PNG exports use the same tempo-evidence wording as the report.

## Performance and MP3 interoperability

- Reserve bounded decoder PCM capacity from the validated duration, avoiding geometric buffer
  growth. On an Apple M4, a synthetic one-hour 44.1 kHz mono WAV peaked at approximately
  **681 MiB resident memory**, versus **1.26 GiB** in 0.7.0—a reduction of approximately **47%**.
  Analysis took approximately **9.3 seconds** on that host. These are local measurements,
  not performance guarantees; decoding still retains whole-track mono PCM.
- Fix ID3v2.3 Camelot user-text encoding for independent metadata readers. Newly written
  TempoKey fields use compatible Latin-1 text; existing metadata is retained unchanged.
- Accept valid empty ID3 tags when saving tagged copies.

## Repeatable validation tooling

- Add the local `tempokey-benchmark` Swift executable and documented JSON manifest format.
- Report per-file timing, duration, detected BPM/key, tempo evidence and failures; continue
  through mixed-success batches.
- Support independently supplied reference labels, a 2% BPM tolerance, exact key comparison,
  separate half/double-time metrics and an optional `--require-labels` gate.
- Unlabeled recordings are explicitly excluded from accuracy denominators. Reports omit
  audio, embedded lyrics/artwork and absolute source directory paths.
- Add CLI integration checks and regressions for silence, confidence, key voting, timeline
  gaps, ID3v2.3 encoding, reference validation and 2,000-file folder enumeration.

## Validation and limits

- **59 core + 39 hosted macOS tests pass (98 total)**; details are in `docs/VALIDATION.md`.
- Three supplied real MP3s analyzed in the sandboxed Release app and in the local benchmark.
  Tagged copies preserve audio payloads and unrelated metadata, including artwork/lyrics;
  original SHA-256 hashes remain unchanged. No supplied music is included in this release.
- Verified native save-panel MP3 export outside the original folder, dark/light report views,
  zoom/pan buttons and the accessible overview adjustment.
- Independently reviewed analysis changes; the cross-gap smoothing finding was reproduced
  and fixed with focused regressions and a full-suite rerun.
- Tempo/key estimates remain heuristic. The supplied recordings lack independently curated
  reference labels, so this release does **not** claim measured real-music accuracy gains.
- Physical microphone/device-removal tests, audible metronome/loop timing, external-drive
  scenarios, exhaustive keyboard/VoiceOver testing and Intel/minimum-OS runtime validation
  remain outstanding. Windows/iOS and broader meter/semantic-section research remain deferred.
- Existing format limits remain: tagged MP3/M4A copies only; M4A key/Camelot are comments;
  analyzed libraries and corrections remain session-local.
